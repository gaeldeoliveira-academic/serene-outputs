# Public document preflight amendment (package0.2.2)

Package0.2.2 combines the qualified count planner with a public bounded document preflight for N13 preparation. No wire/schema/Python/codec semantics change. The qualified0.2.1 source/install are preserved in `history/before_document_preflight/qualified_0_2_1_20261108`,130-file manifest SHA-256 `8f9666b68cfc3b6992d6935a2f784edb9c6d2cdb7f32c16fac61b1d4861c1f31`. Both `build/install-extensions` (0.2.0) and `build/install-capacity-planner` (0.2.1) remain immutable. The new prefix is `build/install-document-preflight`, Release `/MD` and Debug `/MDd`; its install manifest SHA-256 is `0bac1d6cce8e185e9f449fcd75262c9a73f53e7d26a69b9f5d447780fdb52715`.

Include `serene/outputs/document.hpp` and link the archive component. `preflight_document(const DocumentView&, DocumentPreflightLimits={}) noexcept` returns `expected<DocumentPreflight,Status>`. Limits explicitly specify `document_bytes`, `document_parser_budget_bytes`, `metadata_budget_bytes`, `workspace_budget_bytes` and `copy_tile_bytes`. The result reports `kind`, `source_bytes`, `parser_charge_bytes`, admitted `workspace_bytes` and exact retained-byte `sha256`.

- `inactive`: disabled/unavailable documents require zero source bytes. No callback or parser is called; digest and charges are zero. Media/parser limits are inapplicable.
- `json_document`: included `application/json` is materialized only within the configured document byte ceiling and parsed under the same strict generic document grammar/complexity charge as actual verified spool import. Any strict JSON value is allowed, including arrays/scalars and escaped NUL. Duplicate keys, malformed/truncated UTF-8, BOM, invalid control bytes, nonfinite values and malformed JSON are rejected.
- `retained_bytes`: partial documents or other media stream in bounded tiles and are hashed without a complete-JSON claim. Included empty binary content is retained; included empty JSON is invalid. The4GiB wire extent applies to all retained documents; `document_bytes` is specifically the complete-JSON materialization ceiling, matching `SpoolLimits` semantics. A smaller raw-document policy remains a caller bound.

Retained media must be nonempty valid UTF-8 under this supported producer API. This explicit producer policy preserves the previous common-original helper requirement; it does not strengthen generic wire admission of other media strings. Core uses `application/json`. The API does not validate metadata-object or JSONL-record profiles, which have different existing rules.

One `admit_document_json` operation in the existing spool reader calls the established complexity scanner and strict parser. Public preflight and actual spool document reads share that operation; the common-original helper uses the same preflight implementation plus its authored-digest comparison, preserving verification before parsing. There is no copied parser in Core and no second document grammar in Outputs. Source callback failures propagate unchanged. The returned digest can be compared with Core's authored/retained identity; bytes must remain immutable through actual saving.

Workspace charges cover this standalone document operation, including raw materialization, conservative parser complexity and bounded overhead. Successful document preflight proves the configured document/parser admission, not the whole future archive graph or its concurrently resident metadata. Core must also enforce its count/metadata/provenance reservation and actual spool-workspace admission. Complete documents may be preflighted before activation; partial evidence remains unparsed. Initial bundle import still separately rejects partial original-input spools as an unsupported capability.

The narrow source delta is new public `document.hpp`, an include in private `spool_reader.hpp`, and shared validation dispatch in `spool_reader.cpp`. Count planner, archive serializer, bundle assembly, codec and wire spec bodies are unchanged. Package metadata is0.2.2; the unchanged writer identity remains0.2.0.
