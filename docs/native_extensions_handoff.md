## Producer and merger API

`PreparedExport::prepare` owns immutable descriptions, typed diagnostic dictionaries/criteria, and immutable per-row codec profiles. It computes checked directory capacity, working buffers and a conservative finalized-file bound before activation. `ExportLimits::provenance_bytes_bound` bounds the aggregate source bytes supplied during saving; callers should use their actual finite bound for quota planning. Diagnostic authored capacities are positive u64 values; retained rows remain limited to 2^40 and the authored capacity. Impossible checked file bounds fail with `resource_limit`, without redefining the wire capacity grammar.

`DiagnosticRecords` borrows immutable contiguous records or an allocation-free source callback. The writer streams typed lossless columns without a second history. Static certified rows require all six valid metrics; criteria admission and count/capture rules follow the accepted contract. Summary count/min/max are verified against retained valid rows; mean and optional median remain producer assertions checked against correctly rounded extrema. Core-only event/status dictionaries are not inferred from writer name.

`CodecProfile` is immutable and model-only. Empty profile descriptions normalize to one reversible profile. Fixed accuracy is limited to transient rows and the pinned ZFP profile; all values are verified before compressed acceptance or raw fallback. The exact ten-file shared source snapshot remains `docs/codec_extensions_snapshot.json`, SHA-256 `707876ace9cce97772480c324a29fcc5152ebc6dd722b28655296ae9a0afe446`. Its immutable copy is `history/codec_extensions_v2`. The codec owner's exhaustive exponent/exact-real/zero-allocation qualification is retained in `build/extensions-codec-msvc/qualification.json`.

`IndexedProvenanceView` supplies the pre-solve authored digest, five document roles and ordered log sources. Included empty states are preserved. Multiple sources are distinct from binary-section aliases; unknown optional JSON fields cannot create ownership. `ArchiveSession` selects 1.0 when no extension is used and 1.1 with exactly the used supported feature subset otherwise.

`PreparedBundle::prepare(BundleDescription, BundleLimits)` takes the authoritative catalog and each selected run's checked section/source/file bounds, including uncommitted runs. Its plan explicitly reports global directory/catalog, one-spool remap, copy and serialization buffers, one spool-validation workspace reservation and conservative final archive extent. The caller retains original input bytes from the immutable authored snapshot. No input file is reopened. Source parsing is bounded separately from byte copying; included JSON is checked before any imported spool is resident.

`VerifiedSpool::open` requires a trusted immutable manifest binding: exact file extent/hash, authored input digest, run identity and nonempty producer/dependency identities. This detects corruption and binds producer assertions; it does not authenticate an external producer. The initial importer supports finalized single-run 1.0/1.1 archives with the qualified profiles. Unbound, multi-run or partial-original imports return `unsupported_feature`; valid partial original evidence remains valid under the wire contract. Validation checks the complete ownership graph and source-used bitmap, all section hashes, trace/source/column semantics and expected-profile frame decoding before a spool can be copied. This API intentionally verifies the whole imported spool; lazy selection is provided by the separately qualified Python reader. A 1.1 compressed-header profile mismatch maps to `codec_failure`; unchanged 1.0 classifications remain intact.

`BundleSession::append_verified_spool(global_index, handle)` consumes the handle on an append attempt. The global index preserves authored catalog order even when execution/copy order differs. Only the spool's original-input role is replaced with the common original source; a source shared by another role is copied separately for that role. Other document and log sources retain their exact bytes/state. Frame payload, frame index, profile tables, verification arrays and typed diagnostic arrays are copied and rehashed in bounded tiles, without recompression. A complete streamed file hash/extent recheck after copying detects mutation beyond copied sections. Retained disk spools support retry after numerical histories have been released.

If any donor retained original bytes, common original bytes must be included. Otherwise common original state is unavailable if an enabled capture failed, or disabled if all donors disabled it. Extra retention is allowed only through explicit caller policy. Core's initial CLI derives the union from selected runs, with no new retention flag. The prepared bundle and borrowed original bytes outlive its session; an atomic lease rejects overlapping sessions on the same prepared resources. Publication uses a sibling exclusive temporary file, checked write/seek/flush/close and no-replace final publication. No power-loss durability or cryptographic producer authentication is claimed.
