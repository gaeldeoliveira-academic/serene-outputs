# Count-only capacity planning amendment (package0.2.1)

This additive model API supports N13 all-selected reservation before dependent native catalogs can be prepared. It changes no wire, schema, Python or codec semantics. The qualified0.2.0 source and install are retained in `history/before_capacity_planner/qualified_0_2_0_20261108`, manifest SHA-256 `934d2115fbef7ed49239ffec4563245dbdb938089e584a625cfca5da541a8dea`. Active N14 continues using the untouched `build/install-extensions`; the amendment uses `build/capacity-planner-msvc` and `build/install-capacity-planner`.

`plan_export_capacity(const ExportCapacity&, ExportLimits={}) noexcept` returns `expected<WorkspacePlan,Status>` without allocation or retained state. `ExportCapacity` contains run kind, scalar/record/profile capacities, the effective-request inclusion flag, indexed-provenance flag, maximum log sources, an explicit owned-metadata byte ceiling and a borrowed span of `{DiagnosticKind,record_capacity}`. No identity strings, dictionaries, criteria, catalogs, source bytes or solver state are fabricated. `WorkspacePlan::source_capacity` supplies the normalized merger source bound (indexed five documents plus log capacity; legacy six sources).

The metadata ceiling bounds the actual `PreparedExport::plan().metadata_bytes`: owned object, vector and string capacities, including diagnostic dictionaries and effective-request text. It is not serialized JSON length. `ExportLimits::provenance_bytes_bound` bounds every document/log/configuration/info ByteSource. Core must include solver/sampling/execution documents, log-info documents and any other auxiliary source; Outputs has no implicit8192-byte allowance. Each document must also pass the configured parser/document/workspace admission at its actual preparation/import stage. A byte ceiling alone does not prove JSON parser complexity fits memory.

The pure planner charges the full metadata ceiling to returned workspace and checks the supplied workspace/metadata budgets. Core chooses feasible immutable ceilings for every selected run before the first solve and reserves all resulting file bounds, including uncommitted runs. Once each legitimate native context becomes available, actual counts/profiles/trace capacities, owned metadata and total provenance bytes must fit those ceilings before activation. The exact prepared plan must fit the reserved plan. A failure is an honest preparation failure; unknown future state cannot silently enlarge the reservation.

`PreparedExport::prepare` still validates exact identities, real catalogs, effective JSON, immutable profile choices and diagnostic dictionaries/criteria. After measuring owned metadata, it delegates all frame/section/workspace/file arithmetic to the same public count planner. There is no duplicated serializer formula in core or a second planning implementation in Outputs.

For frame width F, transient outer/inner are C/K; static outer/inner are K/C. Maximum frames are `outer*ceil(inner/F)`, limited to2^32. Sections are `61+3*effective_included+(indexed?17+4*L:8)+sum(trace_sections)`, with per-kind trace increments5/19/12/18/12. The finalized-file bound includes raw value capacity,102 bytes per frame for index/verification, exact axes/mapping/table bounds, twice owned metadata ceiling, nine times aggregate source bytes, bounded JSON metadata sections and typed trace widths32/96/81/88/54. Every addition/multiplication is checked against the maximum signed file extent. Diagnostic authored capacity is not clamped to2^40; only retained rows have that wire limit. An overflowing authored bound fails `resource_limit` before execution.

The focused test matrix compares every returned field against exact preparation for transient/static ×legacy/indexed ×effective-included/disabled. It checks zero planning allocations, monotone ceilings, exact and one-byte-short budgets, empty populations,2^32 frame boundary, invalid kind/count/source limits and u64 trace/source bound overflow. Existing model and relevant archive/bundle regressions are retained; the installed consumer imports model only and rejects accidental codec/archive dependencies. Release uses `/MD`; Debug uses `/MDd`.

Build with `tools/build_capacity_planner.cmd Release` and `Debug`. The exact existing offline dependency remains `build/dependencies-extensions/zfp-1.0.1.tar.gz`; no codec suite or Python package rebuild is required. Commands, final identities, delta and old-install preservation are sealed separately in `build/capacity-planner-msvc/qualification.json`.

Both configurations passed the four focused CTest groups (capacity planner, existing model, archive and bundle) and a copied model-only consumer against a relocated installed prefix. That consumer imports neither codec nor archive targets.
